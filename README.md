# DesktopLayoutSwitcher · 桌面布局切换工具

在宿舍的小屏、实验室的大屏之间切换时，恢复各自的桌面文件、快捷方式、图标位置和已打开窗口的位置。**桌面上的实际文件夹只恢复图标位置，增删不参与场景切换，内部内容不读取、不复制、不搬动。** 适用于 **Windows 10 / 11 x64**，中文图形界面，不需要安装 Python 或额外运行时。

## 下载与安装

打开 [最新 Release](https://github.com/lsx20040710/DesktopLayoutSwitcher/releases/latest)：

- **`DesktopLayoutSwitcher-版本号-Setup-x64.exe`**：推荐。按当前用户安装，无需管理员权限，可分别选择程序安装目录和配置目录；安装后从开始菜单启动，可选创建桌面快捷方式。
- **`DesktopLayoutSwitcher-版本号-Portable-x64.zip`**：解压到固定目录，双击 `DesktopLayoutSwitcher.exe`。请保留同目录的脚本和模块。
- `SHA256SUMS.txt`：下载文件的 SHA-256 校验值。

使用系统自带的 64 位 Windows PowerShell 5.1。安装包目前未做代码签名，Windows 可能显示发布者未知；请核对下载来源和校验值，并按所在单位的运行策略使用。

## 建立两个场景

1. 在实验室整理桌面和窗口，输入 `实验室`，点击 **保存当前布局**。
2. 到宿舍后，手动移走不常用的桌面文件或快捷方式，整理图标和窗口，输入 `宿舍`，点击 **保存当前布局**。
3. 以后选择目标配置，点击 **恢复所选配置**。目标场景缺少的文件和快捷方式会补齐，当前桌面多出的文件和快捷方式会被收纳，然后恢复图标和窗口位置。实际文件夹始终保留现状。
4. 给某个场景新增、移走或重命名文件、快捷方式后，请再次保存该场景。配置清单不会在后台自动改写。

屏幕大小不决定项目数量：每个配置都有自己的项目清单，大屏和小屏都可以保存更多或更少项目。当前版本由你选择场景并点击恢复，连接显示器不会自动切换。

第一次建立不同场景时，可先保存文件和快捷方式多的场景，再手动移走不想显示的文件和快捷方式，保存另一个场景。已经保存的文件和快捷方式有恢复副本，其他场景需要时仍能补齐。重要资料仍应保留独立备份。桌面实际文件夹的新增、删除、内部修改均不会被布局恢复撤销。

## 项目如何保存和切换

- 保存时记录需要随场景切换的用户桌面文件和快捷方式清单，并保留恢复副本；共享项的内容除外。
- **实际文件夹只记录图标坐标**。保存、恢复和取回操作不递归读取、不计算内容校验值、不备份、不收纳，也不重建已删除的文件夹；新增文件夹不会因旧布局而被移走。指向文件夹的 `.lnk` 仍按快捷方式处理，不读取它指向的文件夹。
- 切换时把多余的文件和快捷方式移入独立收纳库，不送入回收站。以后需要该项目的场景会把它移回来。
- 场景中的同一文件或快捷方式共用实际内容；修改随实际项目保留，不会被旧恢复副本覆盖。仅在实际项目缺失时使用恢复副本。
- 同名但类型不同、目标已有冲突、项目被占用或无法安全读取时，操作会停止并提示，不覆盖现有文件。
- **取回收纳项目** 将收纳库里的非共享文件和快捷方式取回桌面，方便找回未加入某个配置的新增项目。旧版收纳的文件夹和共享项继续保留在收纳库，不自动取回。
- **仅恢复位置** 可保留当前项目集合，只恢复图标和窗口位置。
- **刷新列表** 只重新读取显示器、配置和状态信息，不改变当前桌面。
- 公共桌面中的快捷方式、回收站等系统图标和工具入口为所有场景共有；可以恢复位置，实际项目不随场景移走。
- 删除配置只删除该配置的 JSON 文件，不删除桌面文件、恢复副本或收纳项目。

## 始终保留在桌面

左下角的 **始终保留在桌面** 按钮可配置不随场景切换的文件和快捷方式。**所有实际文件夹都会自动保留，无需逐个勾选。** 旧版默认的 `Apps` 名称规则仍可保留。

- 共享项的内容不参与场景保存或恢复，不扫描内部文件，不复制备份，也不随切换搬入或移出收纳库。它的桌面图标位置仍会保存和恢复。
- 勾选或取消勾选后保存，只更新共享规则，不立即移动任何文件。后续保存、恢复或取回操作才会使用新规则；普通场景项目的切换方式不变。
- 规则保存在配置目录下的 `data/shared-items.json`，适用于所有场景，它不是一份布局配置。
- 旧布局中记录过的实际文件夹，现在恢复时也会跳过内容操作，只恢复现有图标的位置。程序不会为此改写旧布局 JSON，也不会删除已有恢复副本或备份。
- 旧版已收纳的文件夹，以及现在设为共享的文件或快捷方式，会继续留在收纳库。恢复布局和 **取回收纳项目** 都不会自动取回它们。状态区域会显示保留存档的数量及路径；请手动检查，避免覆盖桌面上已有的同名项目。

例如，桌面的 `Apps`、科研项目、资料等实际文件夹始终留在原路径，内部的 pnpm 依赖或其他内容不参与布局处理；宿舍与实验室可分别摆放不同的文件夹快捷方式。

## 原版本升级

最初版本的 JSON 只有图标和窗口坐标，没有文件内容。旧配置仍可恢复位置，**重新保存一次后**才会记录文件和快捷方式清单及恢复副本；旧配置无法凭名称重建从未备份过的快捷方式。v1.1.0 / v1.1.1 布局里的文件夹记录会被忽略，不需要先重写这些配置。

升级时在安装向导中选择原有配置目录即可继续使用原数据。需要导入最初版本的布局时，可点击 **打开配置目录**，手动复制原布局 JSON。安装包不携带作者的个人布局或指向作者电脑路径的 `.lnk`。

## 数据位置与恢复

安装向导中有独立的 **配置目录** 选择页，可以选到 D 盘等位置；程序安装目录与配置目录分别选择。已有目录选择会作为默认值；从未选择过时默认 `%LOCALAPPDATA%\DesktopLayoutSwitcher\profiles`。按钮 **打开配置目录** 打开当前实际使用的位置。

目录选择保存在 `%LOCALAPPDATA%\DesktopLayoutSwitcher\storage.json`，这个小文件只记录路径，不存桌面项目内容。场景 JSON、上一次配置的 `.bak`、`data` 下的项目索引、文件和快捷方式恢复副本及事务日志保存在所选配置目录。命令行显式传入 `-ProfileRoot` 时，以该参数为准。

**更换配置目录不会自动迁移、复制或删除原目录中的布局、备份和收纳库。** 选择空目录后会使用新的布局集合；要继续使用原来的布局，请选择原目录。v1.1.0 / v1.1.1 已生成的大型文件夹备份不会在升级时自动清理，更换目录也不会释放它们占用的空间。请先通过旧目录及状态显示的收纳路径手动检查；其中可能保留唯一的文件副本。

通常收纳库位于所选配置目录的 `data\vault`。如果桌面与配置目录不在同一个盘，工具会在桌面的父目录建立隐藏的 `.DesktopLayoutSwitcher-vault` 收纳库，保证实际文件和快捷方式在同一盘上原子移动。请不要随意删除或修改收纳库和数据索引；备份用户数据时需同时备份此收纳库。

切换前写入事务日志；操作失败会回滚，程序被中断时下次启动会检查并恢复未完成事务。升级后若发现旧版未完成的事务，仍可能进行一次原移动的回滚，以归还旧版已搬动的项目。无法恢复的冲突会显示错误，请保留数据目录并解决占用或同名问题后重新打开。卸载保留用户数据和收纳项目；删除数据前请先 **取回收纳项目**，再按状态提示的路径检查并备份保留的文件夹和共享存档。取回按钮不会自动恢复这些存档。

取回按钮只恢复未被设为共享项的正式收纳文件和快捷方式。收纳库的 `recovery` 子目录还可能保留中断操作的准备或恢复副本，请手动检查并保留有用内容；它们不会自动覆盖桌面文件。

## 使用边界

- 在桌面右键 → 查看，关闭 **自动排列图标**。工具会在移动文件前检查并提示。
- 保存和恢复时，显示器的分辨率、缩放、主副屏关系应与保存时一致。工具不会修改 Windows 显示设置。
- 同名图标会各匹配一次，但显示名相同的不同快捷方式仍可能交换位置，建议使用不同名称。
- 窗口恢复只移动已经打开的窗口，不启动程序；管理员程序的窗口可能无法由普通权限工具移动。
- 桌面实际文件夹（包括目录联接）均跳过内容处理，其中的 pnpm 依赖不会阻碍保存。不要为了布局保存删除项目内部的链接。
- 非共享的文件若包含符号链接或云占位重解析标签，仍会被保守拦截。OneDrive 文件下载后若仍带重解析标签，可设为共享项保留原位，或使用普通本地文件副本。
- 文件和快捷方式仍需要读取与备份；很大的单个文件会占用时间和空间，可设为共享项保留原位。实际文件夹不会被递归处理。
- 编辑器原子替换文件时，原实体已缺失且没有独立收纳副本，会沿用原项目身份并保留新内容。有独立收纳副本或原实体仍以其他名称存在时，新同名文件会触发冲突提示。不同项目请使用不同名称。

## 命令行

在 64 位 Windows PowerShell 中运行：

```powershell
.\DesktopLayoutSwitcher.ps1 -Action Save -Profile 实验室
.\DesktopLayoutSwitcher.ps1 -Action Restore -Profile 宿舍
.\DesktopLayoutSwitcher.ps1 -Action Restore -Profile 宿舍 -PositionOnly
.\DesktopLayoutSwitcher.ps1 -Action Status
.\DesktopLayoutSwitcher.ps1 -Action Recover
```

使用 `-ProfileRoot D:\LayoutProfiles` 可指定其他数据位置，并覆盖安装时保存的目录选择；该参数不会改变持久的目录选择。两个实例不能同时操作同一个配置目录。

## v1.1.2 修复

[严重 Bug #1](https://github.com/lsx20040710/DesktopLayoutSwitcher/issues/1)：v1.1.0 / v1.1.1 对未设为共享项的实际文件夹递归读取、校验并复制备份，可能导致保存长时间阻塞及配置盘空间耗尽。v1.1.2 将所有实际文件夹改为仅恢复图标位置，忽略增删与内容变化；保存、恢复、取回均跳过文件夹内容。既有文件夹存档保留，供用户检查，不会自动删除。

安装向导新增配置目录选择，支持把后续配置与文件、快捷方式恢复副本放到其他盘；目录选择与程序安装位置独立。

## 开发、测试与发布

主脚本保留原来的 WinForms 界面及 Win32 图标/窗口定位实现。`DesktopItems.psm1` 负责项目集合、恢复副本、收纳及事务恢复。

Windows 上使用 `build/Build-Release.ps1` 运行检查和生成安装包，需要 Inno Setup 6。日常使用不需要构建工具。

GitHub Actions 在 Windows 上解析 PowerShell 源码、编译原生辅助 C# 和启动器，运行临时桌面目录的项目切换、跨盘收纳与事务测试，再验证静默安装、卸载和用户数据保留，成功后生成安装包、便携 ZIP 和校验文件。`main` 中 `VERSION` 指定尚未发布的版本时，工作流创建对应标签并发布 Release。真实 Explorer 桌面、不同 DPI 和显示器的恢复效果仍需在 Windows 实机上验证。
